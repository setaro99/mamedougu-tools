## この章の目的
読者が自分のリポジトリで「毎晩1回エージェントが走る」最小構成を再現できるようにする。コピーして動く雛形を §テンプレート章 と対応させる。

## 骨子（本文で書くこと）
- **3つの部品**: ①定時起動する GitHub Actions ワークフロー（cron） ②その中で Claude Code を実行するステップ ③毎回エージェントに渡る「憲法」ファイル（やってよいこと・禁止・手順書の地図）。
- **ワークフローの骨格**: `on: schedule: - cron:` で起動 → チェックアウト → 必要ツール導入（例: 日本語フォント `fonts-noto-cjk`、画像生成の Pillow、PHP 等は用途次第） → Claude Code 実行 → 生成差分を commit & push。**push はワークフローが行い、エージェント自身はしない**設計にした理由を書く。
- **『憲法』ファイルの役割**: プロンプト最上位に置く1枚。会社概要・実行環境の制約・ディレクトリ地図・1営業日の手順・**番号付きの禁止リスト（ガードレール）**・品質基準・指揮系統を含める。これが「どのモデルでも同じ品質で回る」土台。
- **時計とタイムゾーンの罠**: cron の起動時刻は指定どおりには来ない（§落とし穴で実測）。日付が日をまたいでぶれると日報の欠落や二重処理を招く。→ **実行環境の時計を業務日付に合わせてオフセットする**という当社の回避策を、その動機とともに書く。
- **権限の最小化**: ワークフローの `permissions` を絞る。特に `GITHUB_TOKEN` では触れないものがある（§落とし穴の workflow 権限）。
- **秘密情報の扱い**: Secrets に入れるもの/入れないもの。エージェントに認証情報を「渡さない」ための境界。

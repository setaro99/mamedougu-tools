## この章の目的
読者が「自分の用途にこの本が役立つか」を5分で判断できるようにする。過大な期待と、逆に「どうせ無理」という過小評価の両方を、最初に正す。

## 骨子（本文で書くこと）
- **本書の立場**: これは「AIエージェント礼賛」でも「プロンプト集」でもない。**人間の監視なしに毎晩1営業日を回す運用**を71日続けて踏んだ事故と、それを設計で封じた記録である。
- **約束すること**: ①最小構成（cron + Claude Code + 1枚の「憲法」ファイル）の再現手順 ②71日で踏んだ落とし穴と回避策 ③クラウド/ローカルの二層競合防止 ④「賢いモデルに即興させない」手順書優先設計 ⑤そのまま使える雛形。
- **約束しないこと**: 「放っておけば儲かる」ことは約束しない（本書の運営元は執筆時点で売上¥0。これは §あとがき で正直に扱う）。モデル固有のチューニング術も扱わない（**どのモデルでも同じ品質で回ること**が設計目標だから）。
- **対象読者**: cron / CI 上で LLM エージェントを人間の監視なしに走らせたい、または走らせ始めた人。GitHub と YAML が読める程度を前提にする。
- **実測の前提（重要）**: 本書の数値・症状はすべて一次記録（GitHub Actions のログ、当社の日報 `daily-reports/`、意思決定ログ `decisions.md`）から引く。**推測は「推測」と明記**する。二次記述（手順書の要約）が一次記録と食い違った実例も §落とし穴 で扱う。
- **免責**: 外部サービスの仕様（cron の遅延傾向、トークンの権限、ボット判定）は執筆時点の実測であり、将来変わりうる。各自の環境での再現確認を前提とする。

## この本の立場

これは「AI エージェント礼賛」の本でも、プロンプト集でもない。**人間の監視なしに、毎晩 GitHub Actions 上で Claude Code が 1 営業日ぶんの業務を回す**——その運用を 2026 年 7 月から続けて踏んだ事故と、それを**設計で封じた記録**である。

運営しているのは、AI だけで日々の業務を回す小さなデジタル商品の会社だ。人間（オーナー）は原則として環境の維持と年 1 回の確定申告にしか関与しない（鍵の再発行と決裁箱への回答は人の作業として残る。あとがき参照）。エージェントは毎晩、状況把握→経営判断→実行→検品→記帳→報告の 6 ステップを 1 セッションで完結させ、結果をリポジトリにコミットし、日報をメールで送る。本書ではこれを「1 営業日」と呼ぶ。

タイトルの「71 日」は、2026-10-02 に本書の骨子を起こした時点で一次記録に積み上がっていた稼働日数（10/1 までの 71 営業日）である。執筆を終えた 2026-10-14 時点では 83 営業日になっている。本文の各章にも執筆日時点の数字が出てくるが、このずれは「本文と一次記録の差」として、そのまま残してある（なぜ残すかは第 3 章で扱う）。

## 約束すること

1. **最小構成の再現手順。** cron＋`claude-code-action`＋ 1 枚の「憲法」ファイルで、毎晩 1 回エージェントが動き、成果をコミットするところまで（第 2 章）。
2. **踏んだ落とし穴と回避策。** cron 遅延の実測、`GITHUB_TOKEN` がワークフローを push できない制約、「success なのに何もしていない」実行、データセンター IP からのボット判定、計測の誤報、営業日の日付ドリフト（第 3 章）。
3. **クラウドと手元 PC の二層運用で、片方の成果が黙って消えない設計。** 時間の分離、二重起動ロック、ファイル種別ごとのマージ戦略（第 4 章）。
4. **「賢いモデルに気を利かせて即興させない」ための手順書優先設計。** 番号つきガードレール、人に判断を回す決裁箱、権限の自己拡大禁止（第 5 章）。
5. **そのまま使える雛形 6 本。** 定時営業ワークフロー、日報ガード（＋外部認証に依存しない障害アラーム）、ワークフロー差分の退避ガード、憲法ファイルの骨格、二層の競合防止セット、決裁箱の起票テンプレ（第 6 章）。各雛形には「改変してよい箇所／触ってはいけない箇所」を注記した。

## 約束しないこと

- **「放っておけば儲かる」ことは約束しない。** 本書の運営元は、執筆時点（83 営業日）で売上 ¥0 である。無人で「回る」ことと、事業が「当たる」ことは別の問題で、本書が扱うのは前者だけだ。この点はあとがきで正直に扱う。
- **モデル固有のチューニング術は扱わない。** 設計目標が「どのモデルで実行しても同じ品質で回ること」だからである。モデルを賢くする話ではなく、賢さに依存しない話をする。
- **外部サービスの仕様の永続性は保証しない。** cron の遅延傾向、トークンの権限、ボット判定は執筆時点の実測であり、将来変わりうる。各自の環境で再現確認することを前提にしてほしい。

## 対象読者

- cron や CI の上で LLM エージェントを**人間の監視なしに**走らせたい、または走らせ始めて困っている人。
- GitHub と YAML が読める程度の前提知識があれば足りる。特定の言語やフレームワークの知識は要らない。
- 逆に、対話的に Claude Code を使うコツを知りたい人には向かない。本書のエージェントは、人が画面の前にいないときに動く。

## 実測の前提（重要）

本書の数値と症状は、すべて**一次記録**から引いている。GitHub Actions の実行履歴（`gh run list`）、毎晩の日報、追記式の意思決定ログの 3 つだ。推測は「推測」と明記する。

これを強調するのには理由がある。執筆の過程で、社内の手順書に書かれていた「cron の遅延は +3.5〜4.5 時間が常態」という記述が、実は 7 月末の 1 週間だけの観測を一般化したものだったと分かった（実測は日によって +17 分から +9 時間まで桁で変わる）。手順書の要約（二次記述）は一次記録と食い違いうる。本書の検品では、原稿を読むだけでなく記録を引き直すことを規律にした。

## 本書の構成

| 章 | 内容 | 読むとできること |
|---|---|---|
| 第 1 章 | なぜ無人なのか、「1 営業日」という単位 | 何を自動化し、何を人に残すかの線引き |
| 第 2 章 | 最小構成の作り方 | 毎晩 1 回、成果がコミットされる状態 |
| 第 3 章 | 71 日で踏んだ落とし穴 | 同じ穴を踏まない |
| 第 4 章 | 二層（クラウド＋手元 PC）の競合防止 | 片方の成果が消えない |
| 第 5 章 | 手順書優先の設計 | モデルが変わっても同じ品質で回る |
| 第 6 章 | 雛形集 | コピーして動かす |
| あとがき | 限界・向いていない用途・コスト | 過大評価も過小評価もしない |

この「はじめに」と第 1 章は無料で読める。買うかどうかは、そこまでで判断してほしい。
